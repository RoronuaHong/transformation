# 素材中心检索架构实践（画面内容 + 分类型语义）

> 合并自《画面内容检索落地方案》（2026-10-08 落地，全 ✅）与《语义检索分类型对齐方案》（2026-10-08 盘点），2026-10-10 整理为单一检索实践文档。
> 原理性参考见《影视素材片段检索_Netflix路线原理与对齐.md》（独立文档，原理 vs 落地互补）。

## 0. 目标与对齐依据

让"视频/图片画面里出现的内容"（如实物「排骨」）也能被文本检索出来，不依赖画面上的文字或文件名；并对齐业界 DAM / Agentic DAM 最佳实践。

| 来源 | 关键结论 | 本项目落点 |
|---|---|---|
| §16.2 三文件分离 Job4 | 多模态模型读 Proxy + 关键帧，生成画面描述/标签 + 向量写入库 | 核心：抽帧 + VLM 打标 → sidecar |
| §17.2 / §17.4（验证报告 E 维度） | 视觉相似度搜索已落地；以图搜图强、以文搜图弱（零样本 CLIP 对垂类内容） | 文本搜画面不能只靠 CLIP → 主用 VLM 描述 |
| §18.2 能力2 | 多模态语义检索 = 文本搜视频 / 图搜视频 / 相似片段 | 双通道：VLM 描述（主）+ CLIP 文本→帧（补） |
| Cloudinary / Canto / Aprimo（Enrichment·Understanding） | 理解画面是 DAM 核心，不只靠标签/文字 | VLM 生成"画面描述 + 标签"文本 |

## 1. 检索通道全景（当前 `search()` 实际在做什么）

面板每次查询做两件事，然后用 RRF 合并：

1. **词法**：文件名、标签、描述、路径，外加 OCR / 画面描述 sidecar（权重 0.35）。
2. **语义**：把**整条素材**拼成一段文字，用 `bge-m3` 算一个向量；居中余弦低于 `0.25`（环境变量 `VITUAL_EMBED_MIN_COS`）的条目直接丢掉。

这段文字来自 `doc_text()`：文件名、标签、描述、OCR sidecar、画面描述 sidecar、类型、目录末段。因此「语义」搜到的是**这些文字的意思**，不是像素，也不是声波。

已有但**没有接进面板**的能力：

| 能力 | 入口 | 面板是否使用 |
|---|---|---|
| 以文搜图 CLIP | `search_by_text_image` | 自动/语义在文字命中少于 3 条时补入。顶分低于 0.32，或与第二名差距小于 0.03，整批丢弃（挡住 0.28 的印章簇）。文件名/编号/台词意图不走这一路 |
| 长文档分块 | `chunk_search` | 自动/语义把文档和字幕正文追加在已有排序之后。词法模式不读正文 |
| 镜头时间轴 | `get_shots` | 台词或带时间的画面行命中后写入 `hit_t` / `hit_shot`。卡片/详情里视频会 seek 到这一秒。没有给每个镜头单独跑 VLM |
| 重排 | `VITUAL_RERANK_MODEL` | 默认仍关。打开后的候选文本包含画面描述、OCR、转写（各截 400 字） |

## 2. 画面内容检索（两条通道）

### 通道 A（主，VLM 描述）
- 新增派生 sidecar 目录 `index/visual/`，每素材 `index/visual/<id>.txt`（派生、可重建、**绝不写 DB `description`**）。
- 新增 `visual_runner.py`（镜像 `ocr_runner.py`）：子进程调**本地多模态 VLM**（`gemma4:e2b`），对每帧输出「画面描述 + 标签」JSON。
- 新增 `visual_material()`（镜像 `ocr_material`）：ffmpeg 抽帧 → 调 runner → 落 sidecar；幂等、记 history、作用于 `VISUAL_KINDS=(videos, silent, images)`。
- 词法：`_score` 新增 `_VISUAL_FIELD_WEIGHT = 0.35` 独立通道；语义：`doc_text` 拼入 visual 文本 → 进 `bge-m3` 稠密检索；全文：`_material_text` 收录 visual sidecar。
- 效果：查"排骨" → 命中画面里是排骨的素材，即使无任何文字。

### 通道 B（补，CLIP 文本→帧）
- 复用 `clip_runner` + `image_embeddings`，将素材扩展为**每帧一个 CLIP 向量**（原只索引单图，需扩成多帧）。
- 查询文本用 CLIP text encoder 编码比对。文档已证**对垂类弱**，仅作补充通道，不当主依赖。

**铁律**：visual 文本**只能走 sidecar + 独立低权重通道**，**绝不写 `description`**（主排序 1.5 权重）。否则门禁 ndcg 会 0.84→0.80 式退化。

## 3. 分类型语义检索对齐（实库缺口）

语料 384 条，文本向量 `bge-m3:latest` 覆盖 384/384。面板「检索：自动 / 语义」走同一条 `search()`，不是按视频、音频、图片各做一套语义引擎。

| 分类 | 条数 | 文本向量 | 画面描述 | OCR | 语义真正能用的内容 | 缺口 |
|---|---:|---:|---:|---:|---|---|
| 图片 images | 157 | 157 | 157 | 110 | 文件名 + 画面描述文字 | 描述常把具体物体写成「食品 / 砖块」。CLIP 未进面板。鸡翅要靠描述里真有「鸡翅」 |
| 无声 silent | 77 | 77 | 77 | 75 | 同上，整段一个向量 | 多帧 CLIP 几乎没建。不能按镜头搜 |
| 视频 videos | 16 | 16 | **6** | **6** | 多数只有文件名 | 10 条母版没有画面描述。声音里的话没有进这条索引 |
| 动图 anim | 1 | 1 | 1 | 0 | 画面描述 | 与图片同一条路径，样本太少 |
| 音频 audio | 8 | 8 | 0 | 0 | 文件名、标签、短描述 | **没有转写文本**。语义只能撞上「wav / asr / 音轨」这类词，听不出内容 |
| 字幕 subs | 19 | 19 | 0 | 0 | 描述，不是 .srt 正文 | 正文只在 `chunk_search` 里，面板搜不到台词 |
| 文档 docs | 105 | 105 | 0 | 0 | 64 条有描述；41 条几乎只有文件名 | 正文同样只在分块检索，面板整篇一个向量 |
| 其他 other | 1 | 1 | 0 | 0 | 文件名 | 无专门通道 |

鸡翅案例：图在库里，描述写成「橙红色食品 / 红烧肉」，余弦最高约 0.17，低于 0.25，面板返回 0。后来只改正了 3 张已核对画面的描述。

**要对齐的做法**（不引入云端多模态大模型，本地已有 bge-m3 / faster-whisper / 画面 VLM / CLIP）：

1. 词法 + 稠密用 RRF 名次融合，不把两种分数加在一起（BM25/词法与余弦不在一个量纲，本库已在用 RRF）。
2. 视频按场景切段，每段单独索引，而不是整片一个向量（`index/shots` 已有，但检索粒度仍是整条素材）。
3. 语音先转写，再对转写做词法 + 文本向量；命中要能跳到时间（生产系统按说话轮次建索引；CLAP 类「声音↔短标题」对台词语义弱，ACL 2026 ATIR：跨模态音频检索 Recall@1 远低于先转写再做文本检索）。
4. 画面查询走视觉通道，专有名词走词法；两类查询不要挤在同一个 0.25 门槛后面。
5. 重排只看召回后一小截，候选文本必须含画面描述、OCR、转写（现在重排文档把这些 sidecar 排除了，精排时看不见真正命中字段）。

**明确不采用**：把 OCR / 画面描述 / 转写写进数据库 `description`（权重 1.5）。历史教训是门禁 nDCG 从 0.84 掉到 0.80。新文本继续只进 sidecar 和独立通道。

## 4. 落地步骤（文件/函数级）

1. `core.py`：加 `VISUAL_DIR`、`visual_sidecar_path()`（镜像 `ocr_sidecar_path`）、`_visual_text()`（带 (mtime,size) 缓存，镜像 `_ocr_text`）。
2. `core.py`：在 `_score` / `doc_text` / `_material_text` 三处各插入 visual 通道（权重 0.35，不碰主字段）。
3. `core.py`：加 `visual_material(mid, frames=N, force=)`，ffmpeg 抽帧逻辑复用 OCR 的（视频按关键帧/均匀采样，图片单帧）。
4. `visual_runner.py`：新文件，调本地 VLM 出「描述+标签」JSON（UTF-8 双保险，同 ocr_runner）。
5. `core.py auto_process_material`：链改为 `make_thumb → tech → describe → ocr → visual → shots → phash`，新素材入库即自动出画面描述。
6. `cli.py`：加 `visual <id>|--all [--apply]`（镜像 `ocr`，含 `--all`/`--limit`/`--force`）。
7. `mcp_server.py`：加 `run_visual` 工具（写 sidecar → 需 `confirm=true`，同 `run_ocr`）。
8. 帧采样策略：视频默认均匀抽 N 帧（同 OCR 的 frames=5），可选复用 `build_shot_index` 关键帧提升覆盖。
9. 通道 B：扩展 `image_embeddings` 支持多帧；新增文本→帧比对入口（`cli.py imgembed --frames`）。

## 5. 约束（铁律 + 门禁）

- **铁律**（§23.3 / OCR 教训 / §24.3 三合一）：visual 文本**只能走 sidecar + 独立低权重通道**，**绝不写 `description`**。否则门禁 ndcg 会 0.84→0.80 式退化。
- **门禁不退化**：任何改动先跑 `eval_search.py --mode lexical --gate`（基线 p5 .71 / r20 .78 / mrr .85 / ndcg .84，容差 .02）。新增**人工标注 GT 查询**（如"排骨"→ 画面有排骨的素材 id 集合）验证真能召回。
- **异步消化**：抽帧 + VLM 推理进现有 `enqueue_autoproc` 后台异步链，不阻塞 API。

## 6. 前置：本地多模态 VLM 可用性

当前 ollama 已装：`bge-m3 / nomic-embed-text / gemma4:e2b / translategemma:4b / 两个 bge-reranker`。**无一确认是多模态（看图）模型** 的担忧已解除——`gemma4:e2b` **已确认支持 vision**（本地、离线可用）。若否，则 `ollama pull` 一个视觉模型（llama3.2-vision / gemma3:4b-it / qwen2.5-vl / minicpm-v）。环境标称"全离线"，但 bge-m3 / reranker 是近期拉到 → 联网拉模型间歇可用；需确认网络/磁盘（视觉模型 2–8GB）。

## 8. 分类型分步对齐（已落地 2026-10-08）

步 1–5 已落到代码，词法门禁 PASS（p5 0.80 / r20 0.78 / mrr 0.91 / ndcg 0.91，基线 0.71 / 0.78 / 0.85 / 0.84）。每步都保持 `eval_search.py --mode lexical --gate` 不退步。

- **步 1 — 把已有通道接进面板，按类型分流**：图片/无声/视频/动图词法命中少时并入 `search_by_text_image` 高分结果并标命中来自画面；文档/字幕并入 `chunk_search` 命中正文段落；音频/纯文件名查询仍只有现有文本向量。语义模式下列出命中依据（文件名/画面描述/字幕段落/画面向量）。
- **步 2 — 补齐视频画面描述，并改成按镜头**：先补 10 条无 `index/visual` 的视频（描述要具体物体，拒答句不入库）；检索单位从「整条视频一个向量」改为「每个 shot 一段描述 + 一个向量」，带回 `t_start`；多帧 CLIP 从 2 条扩到视频类（只做补充召回，主证据仍是画面描述文字）。
- **步 3 — 音频与带声视频的台词**：不重跑 Whisper（流水线已写 `.srt`）；同 `job:` 下优先 `zh.srt` 挂到该任务视频/音轨为 `index/asr/<id>.txt` 每行带时间；词法走独立 0.35 通道、语义经 `doc_text` 读 sidecar，不写 `description`；多语字幕不全部挂上；命中行带时间范围。
- **步 4 — 查询意图与门槛**：文件名/id/扩展名/`type:`/`job:` 词法优先、语义门槛维持 0.25；看画面（食物/物体/场景）允许视觉通道较低门槛且必须带回画面证据；听内容（说了什么/台词）只走转写/字幕通道；重排候选文本改为 name + description + 画面描述 + OCR + 转写片段，默认仍关。
- **步 5 — 验收**：鸡翅（auto P@5 0.60 / R@20 1.00 / MRR 1.00，前三名即三张酱汁鸡翅，红印章不挤前）；台词原句命中对应 subs/ASR 时间段；wav/音轨仍能被类型词找到；旧门禁 16 句 lexical gate 仍 PASS。

**已改（2026-10-08，贴链接之后的两处断点）**：

1. 画面描述不算缺项：`pending_processing` 原先只看封面/OCR/镜头/pHash，视频这四项齐了就跳过 `visual_material`。现缺 `index/visual/<id>.txt` 会标成待处理。
2. 字幕和文档正文不进面板：自动/语义检索在原排序之后追加 `.srt`/笔记正文命中，不插到词法结果前；词法模式和门禁路径不变。
3. 台词挂到片子上：`attach_job_transcripts()` 同 `job:` 中文字幕写入 `index/asr/<id>.txt`，视频和音轨用 0.35 权重可搜；`run_job_dir` 登记后会跑；无同任务字幕的成片不凭空出现转写。
4. CLIP 只补空结果：`_append_clip_hits` 文字得分 >0 已有 3 条就不再叫 CLIP；叫了也要顶分 ≥ 0.32 且比第二名高 0.03，否则整批不要；`type:`/`job:`/路径/纯十六进制 id 及带「台词/字幕/说了」的查询直接跳过。
5. 命中时间：`_mark_hit` 用双字词对上转写行或 `[12.5s]` 画面行，填 `hit_t`/`hit_shot`/`hit_end`；面板视频 `onLoadedMetadata` 把播放头放到这一秒，卡片标「台词/画面」。
6. 门槛：全库余弦仍 0.25，没为「看画面」单独下调；画面证据来自 sidecar 词法或间隙 CLIP。
7. 缺画面描述的 10 条视频：9 条源文件无 moov（ffmpeg 报 `moov atom not found`，有的只有几十字节）抽不出帧；`df15038ba7ca` 能打开但开头黑场 VLM 编了「红烧肉」，sidecar 已删未进检索；抽帧快进得空文件时再精确 seek，仍抽不出就保持缺描述。多帧 CLIP 对视频/无声 93 条里 84 条有帧向量（9 条跳过），查询仍过 0.32/0.03 间隙才补进面板。按镜头做法：转写/画面行上的时间落进已有 `index/shots` 场景区间，结果带镜头起点，没逐镜再跑 VLM。

## 9. 这一轮不做 / 明确不采用

- 不换云端视频嵌入，不上 CLAP 作为语音主索引。
- 不把 384 条画面描述全部重跑，只补缺的视频及验收集里确认看错的图片。
- 不改分类法（master / shot / silent / audio-stem 仍按方案 A）。
- 不在本文确认前改排序权重或 `0.25` 门槛。
