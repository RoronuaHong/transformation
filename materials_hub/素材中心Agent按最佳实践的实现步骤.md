# 素材中心 Agent：按最佳实践落地的步骤（多语言）

> 写于 2026-10-08，同日按多语言改过。对照 [素材中心Agent网上最佳实践与商业模式.md](素材中心Agent网上最佳实践与商业模式.md)。
> 只写步骤，不改代码。确认后再做。

本系统的语言不是「中文为主、英文附带」。站点与字幕流水线共用一套 16 语（`transform/lib/locales.ts` 与 `subtitle_pipeline/langs.py` 的 `site` 包，必须一起改）：

`zh`、`en`、`ru`、`ja`、`ko`、`pt`、`de`、`zh-Hant`、`es`、`fr`、`ar`、`hi`、`id`、`vi`、`th`、`tr`。

三层要分开，不能混成「只挂中文」：

| 层 | 现在实际怎么做 | 步骤里必须守住 |
|---|---|---|
| 界面 | 素材中心文案只有简体、英文、繁体是写全的。其余 13 种界面语言的素材中心段落回退成英文 | 新增的命中说明、缺步、复核、就绪原因进 `copy.ts`，三种已写全的语言一起补；其余界面语言至少有英文回退，不出现写死的汉字 |
| 字幕和笔记 | 一种口播源语，加上最多 16 种译文，各自一条文件，标签 `lang:` | 视频/音轨的检索sidecar只挂**一条**源语（简体优先，其次英文），避免 16 种译文把向量冲散。其余语种仍是独立的字幕/笔记条目，用 `lang:` 和正文检索 |
| 查询 | 非中文问句经 `translategemma` 译成简体，再与原文一起检索；语义模型是多语 `bge-m3`。词法只切拉丁字母和汉字（含繁体），不切假名、谚文、西里尔、阿拉伯字母 | 日语、韩语、俄语等问句靠翻译桥和语义，不靠汉字 bigram。收紧噪声时只动汉字 bigram，不动拉丁词，也不要把译文字幕全部挂进母版 |

本机没有市场部和电商。最佳实践里的「发到网站 / 按转化加码」仍是本地链路。多语言不因此改成只服务中文查询。

做的时候继续守住：

- 画面描述、OCR、转写只进 sidecar，不写进 `description`。
- 以文搜图仍要顶分 ≥ 0.32 且比第二名高出 0.03，否则整批不要。
- 分类仍是方案 A：母版 / 逻辑镜头 / 无声画面 / 音轨。
- 每改检索都跑 `python eval_search.py --mode lexical --gate`。门禁句子是中文的，通过之外再看一条英文问句和一条 `lang:` 过滤。

## 步骤

### 1. 入库即跑完，并留下每一步的结果

**做法：** 上传是事件。任何界面语言下打开这条素材，都能看到哪一步成了、哪一步跳过。

**现在：** 自动链是封面 → 技术元数据 → 描述（分辨率/时长/任务号）→ OCR → 画面描述 → 镜头 → 感知哈希。画面描述已要求简体四行加英文四行（`描述` / `标签` / `EN描述` / `EN标签`）。同任务字幕挂到视频/音轨发生在登记时，而且只选简体，其次英文；繁体被排在更后，其余语种不挂到母版。自动链本身不挂。

**要做：**

- 自动链在镜头之后调用 `attach_job_transcripts`。挂接规则不变：一个任务只挂一条源语字幕（简体优先，没有则英文）。繁体和其他 14 种保持为独立字幕条目，不写进母版 sidecar。
- `index/run/<id>.json` 记下各步状态，并记下挂上的 `lang`（如 `zh` 或 `en`）以及同任务还有哪些 `lang:` 没挂（列表即可）。
- 坏文件写跳过原因。画面描述若不是「简体 + 英文」四行，视为这步未完成，不把拒答或单语残句当成功。

**验收：** 带 `job:` 且已有 `zh.srt` 和 `ja.srt` 的成片，母版 sidecar 里只有中文台词；日文字幕仍能按 `lang:ja` 单独搜到。坏文件的记录是原因，不是假描述。

### 2. 角色分开，一条目标串起来

**做法：** 打标、找素材、挑错、出文件、判断能不能发，分开做。用户用 16 种语言里的任何一种描述目标，都进同一条链。

**现在：** 技能入口的关键词覆盖简体、繁体和英文（例如导出 / 導出 / export）。日语、俄语等整句还不会命中这些词。组装包没有先写下「这次要什么」。

**要做：** 匹配技能之前，对不含汉字也不含已知英文技能词的问句，走和检索相同的翻译桥，得到简体后再匹配。回复语言跟界面语言走，不把内部简体计划直接显示给英文或日文界面。brief 里同时留下原文和译后的检索词。

**验收：** 英文 “package 3 indoor dialogue shots” 和简体「组装 3 段室内对话」得到同一结构的 brief。包里的 id 都能在库里打开。

### 3. 模型只往现有词表里填

**做法：** 语言也是受控词表：`lang:` 只用站点 16 个代码（`zh-Hant` 保留连字符）。模型不能发明 `lang:chinese` 或把语种名写进 `tags` 主字段。

**现在：** `lang:` 已是分面。自动描述不写「视频/成品」。画面的中英标签在 sidecar。

**要做：** 理解记录里的语种代码必须来自文件上的 `lang:` 或文件名（`zh.srt`、`zh-Hant.srt`），不来自模型自由发挥。画面中英标签继续只在 sidecar。

**验收：** 词法门禁通过。新素材的 `tags` 里没有模型写的语种别名；`lang:zh-Hant` 不会被收成 `lang:zh`。

### 4. 理解写成字段，片段带时间

**做法：** 下游要读的是字段：画面（中英都要）、台词在第几秒、这句台词是哪种语言、画质、能不能发。

**现在：** 技术元数据在 `index/tech/`。转写带时间。命中可跳 `hit_t`。画面 sidecar 有中英两套。人脸没有人名库。

**要做：** `index/understand/<id>.json` 只汇总已有 sidecar：

- `speech`：挂接语种、起止秒、同任务其他语种代码列表（不把那些正文抄进来）
- `visual_zh` / `visual_en`：画面 sidecar 里已有的两套描述和标签，缺的就空
- `quality`：打不开或黑场为 `unusable`
- `people`：`unknown`
- `rights`：`own`

不把这份 JSON 抄进 `description`。

**验收：** 鸡翅图的 `visual_zh` 含「鸡翅」、`visual_en` 含 chicken wings。母版台词起秒接近 5.76，`speech.lang` 为 `zh`。同任务若有日文字幕，只出现在「其他语种」列表里。

### 5. 人在会改库、会出文件的地方点头

**做法：** 派生处理自动跑。改标签、删除、导出要人确认。确认按钮和「已复核」的说法随界面语言变。

**现在：** 写操作要 `confirm=true`。面板没有按语言切换的复核状态。

**要做：** 自动链仍不需要人点。`reviewed` 默认 false，只有人确认后写成 true，放在理解记录里，不进主排序。简体、繁体、英文三套素材中心文案都有对应句子；其他界面语言用英文回退。

**验收：** 不带 confirm 的导出仍被拒绝。英文界面下看到的是英文复核状态，不是简体标签。

### 6. 找得到之后能交出可用文件

**做法：** 交出的是片段和时间，再加上这一条用的字幕语种。用户要另一种语言时，交独立的字幕文件，不把 16 份都打进视频。

**现在：** 导出按种类分流。字幕文件原样复制。没有把 `lang:` 写进交付说明。

**要做：** 未指定区间时用理解记录里的秒。manifest 写 `speech_lang`。若用户点名 `lang:ja`，导出的是那条日文字幕文件（复制），视频时间仍以源语挂接为准。确认前只给计划。

**验收：** 未确认时计划里同时有时间和 `zh`。点名日语时交付物是 `lang:ja` 的字幕，母版 sidecar 仍不是日文全文。

### 7. 发出去之前看能不能用

**做法：** 坏文件拦住。语言上要看：源语字幕挂上了没有；用户要的那种 `lang:` 在不在这个任务里。缺某一种译文是说明，不是把整个任务判死。

**现在：** 就绪只看封面、镜头、切片父链、有没有母版。

**要做：** 源文件打不开则 `channel_ready` 为假。有声母版没有源语挂接时写进说明。某个 `lang:` 在该任务的字幕里不存在时，写进 blocking 的是「缺这种语言」，任务仍可按已有语言导出。

**验收：** 无 moov 的任务不能就绪。只有中英字幕的任务，查 `lang:ja` 时报告缺日语，查 `lang:zh` 时不因此失败。

### 8. 别的 Agent 读结构化结果

**做法：** 别的 Agent 读字段，不猜散文。字段里的语种用 16 个代码。

**现在：** 已有 `hub://job`、`hub://shots`、`hub://related`。

**要做：** 只读 `hub://understand/{id}`、`hub://run/{id}`。JSON 里的 `lang` 与库内 `lang:` 一致。

**验收：** 读到的 `speech.lang` 与步骤 4 相同。缺 id 报错，不编造某种语言的台词。

### 9. 用本库真有的数字验收

**做法：** 覆盖数按语种拆开，避免「有一条中文」被说成 16 语都齐了。

**现在：** 门禁是中文 16 句。鸡翅和中文台词另有小标注。英文问句靠翻译桥，没有放进同一张验收表。

**要做：** `ops_summary` 给出：画面中英双行齐全的条数、源语已挂接的条数、每个 `lang:` 的字幕条数、坏文件数、导出次数、反馈采纳率。另加两条不进旧门禁分母的检查：一条英文问句（如 chicken wings）、一条 `lang:ja` 过滤能命中日文字幕文件。

**验收：** 语种计数与 `lang:` 标签一致。旧词法门禁仍单独通过。

### 10. 下次组装用上次被人留下的选择

**做法：** 否决要记在译后的检索词上，这样英文和简体否决的是同一条。

**现在：** 反馈日志不区分原文和译后词，组装包也不读它。

**要做：** brief 记录原文语言和译后词。否决按译后词生效。被导出过的 id 仍必须真实存在。

**验收：** 在英文里否决 “indoor dialogue” 的译后词后，再用简体组装同一目标，brief 的第一查询不再是那条词。

### 11. 检索按意图，第一屏就是要的那条

**做法：** 找文件、看画面、听台词分开。听台词时指定了 `lang:` 就查那种语言的字幕文件；没指定就查母版上的源语挂接。汉字 bigram 的噪声收紧不能误伤英文词，也不能要求日文假名去对汉字。

**现在：** 非中文问句会先翻译。意图词只有简体「台词/字幕」。面板上的「台词 / 画面」是写死的简体。一句中文台词会拉出 100 多条，因为汉字 bigram 撞上画面描述。

**要做：**

- 意图词在翻译之后判断（英文 “what was said” 译成简体后再走台词通道）。同时认 `lang:`。
- 只提高汉字 bigram 在转写/画面通道上的重叠要求。拉丁单词权重保持 1。假名、谚文等不新增一套错误的「汉字规则」。
- 面板命中徽章走 `copy.ts`（简体、繁体、英文三套；其余界面语言英文回退）。
- 改完跑中文门禁，再手工看英文 “chicken wings” 和 `lang:ja`。

**验收：** 中文那句台词的前三条仍是母版和音轨，总条数少于现在的 149，门禁通过。英文 chicken wings 的前排仍是那三张图。繁体界面徽章是繁体，不是简体「台词」。

### 12. 工作流固定、可解释

**做法：** 只有一条入库链。解释这步缺了什么时，用界面语言说，步骤 id 用稳定的英文键（`thumb`、`asr`、`visual`），避免 16 套流程。

**现在：** 链是写死的。Agent 技能词未覆盖全部界面语言。

**要做：** 不增加工作流设计器。问答先按步骤 2 译到简体以选链，再按界面语言描述 `index/run/<id>.json`。JSON 的键保持英文。

**验收：** 英文界面问 “what ran on this asset”，答案与 JSON 的步骤键一致，不出现链里没有的工具名，也不把内部键显示成另一种语言的另一套流程。

## 顺序

1 → 4 → 7 → 11，先让挂接语种、理解字段、缺语言的说明、跨语检索变清楚。然后 2 → 6 → 5。最后 8 → 9 → 10。3 和 12 全程守住。

11 若中文门禁失败，只回退汉字重叠那一处。英文问句或 `lang:` 过滤变差，同样只回退 11，不改挂接「只保留一条源语」的规则。
