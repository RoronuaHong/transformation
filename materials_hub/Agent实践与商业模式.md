# 素材中心 Agent 实践与商业模式

> 合并自《素材中心 Agent：按最佳实践落地的步骤》《素材中心 Agent：网上最佳实践与商业模式》《商业 DAM 最佳实践 · 未对齐清单》，2026-10-10 整理。

## 0. 多语言前提（贯穿全文）

站点与字幕流水线共用一套 16 语（`transform/lib/locales.ts` 与 `subtitle_pipeline/langs.py` 的 `site` 包，必须一起改）：

`zh`、`en`、`ru`、`ja`、`ko`、`pt`、`de`、`zh-Hant`、`es`、`fr`、`ar`、`hi`、`id`、`vi`、`th`、`tr`。

三层要分开，不能混成「只挂中文」：

| 层 | 现在实际怎么做 | 步骤里必须守住 |
|---|---|---|
| 界面 | 素材中心文案只有简体、英文、繁体写全；其余 13 种界面语言回退成英文 | 新增命中说明/缺步/复核/就绪原因进 `copy.ts`，三种已写全语言一起补；其余界面语言至少英文回退，不出现写死汉字 |
| 字幕和笔记 | 一种口播源语 + 最多 16 种译文，各自一条文件，标签 `lang:` | 视频/音轨检索 sidecar 只挂**一条**源语（简体优先，其次英文），避免 16 种译文把向量冲散；其余语种仍是独立字幕/笔记条目，用 `lang:` 和正文检索 |
| 查询 | 非中文问句经 `translategemma` 译成简体再与原文一起检索；语义模型多语 `bge-m3`；词法只切拉丁字母和汉字（含繁体），不切假名、谚文、西里尔、阿拉伯字母 | 日语/韩语/俄语问句靠翻译桥和语义，不靠汉字 bigram；收紧噪声只动汉字 bigram，不动拉丁词，不把译文字幕全部挂进母版 |

本机没有市场部和电商。最佳实践里的「发到网站 / 按转化加码」仍是本地链路；多语言不因此改成只服务中文查询。

## 1. 按最佳实践落地的步骤（12 步）

> 写于 2026-10-08，只写步骤不改代码，确认后再做。每步含「现在 / 要做 / 验收」。

### 1. 入库即跑完，并留下每一步的结果
**现在**：自动链 封面 → 技术元数据 → 描述 → OCR → 画面描述 → 镜头 → 感知哈希；画面描述已要求简体四行 + 英文四行。
**要做**：镜头之后调 `attach_job_transcripts` 挂一条源语（简体优先，无则英文）；`index/run/<id>.json` 记各步状态 + 挂上的 `lang` + 同任务未挂 `lang` 列表；坏文件写跳过原因。
**验收**：带 `job:` 且有 `zh.srt`/`ja.srt` 的成片，母版 sidecar 只有中文台词；日文字幕仍能按 `lang:ja` 单独搜到。

### 2. 角色分开，一条目标串起来
**现在**：技能入口关键词覆盖简/繁/英；日语俄语整句还不命中；组装包没先写「这次要什么」。
**要做**：匹配技能前，对不含汉字也不含已知英文技能词的问句走翻译桥得简体再匹配；回复语言跟界面，不把内部简体计划显示给英文/日文界面；brief 留原文和译后检索词。
**验收**：英文 "package 3 indoor dialogue shots" 与简体「组装 3 段室内对话」得同一结构 brief；包里 id 都能在库里打开。

### 3. 模型只往现有词表里填
**现在**：`lang:` 已是分面；自动描述不写「视频/成品」。
**要做**：理解记录语种代码必须来自文件 `lang:` 或文件名（`zh.srt`/`zh-Hant.srt`），不来自模型自由发挥；画面中英标签只在 sidecar。
**验收**：词法门禁通过；新素材 `tags` 无模型写的语种别名；`lang:zh-Hant` 不被收成 `lang:zh`。

### 4. 理解写成字段，片段带时间
**现在**：技术元数据在 `index/tech/`；转写带时间；命中可跳 `hit_t`；画面 sidecar 中英两套；人脸无人名库。
**要做**：`index/understand/<id>.json` 只汇总已有 sidecar——`speech`(挂接语种/起止秒/其他语种列表)、`visual_zh`/`visual_en`(缺则空)、`quality`(打不开/黑场为 `unusable`)、`people`(`unknown`)、`rights`(`own`)；不抄进 `description`。
**验收**：鸡翅图 `visual_zh` 含「鸡翅」、`visual_en` 含 chicken wings；母版台词起秒近 5.76，`speech.lang` 为 `zh`；日文字幕只在「其他语种」列表。

### 5. 人在会改库、会出文件的地方点头
**现在**：写操作要 `confirm=true`；面板没按语言切换的复核状态。
**要做**：自动链不需人点；`reviewed` 默认 false，人确认后写 true（放理解记录，不进主排序）；简/繁/英三套文案都有对应句，其他界面语言英文回退。
**验收**：不带 confirm 的导出仍被拒；英文界面看到英文复核状态。

### 6. 找得到之后能交出可用文件
**现在**：导出按种类分流；字幕文件原样复制；没把 `lang:` 写进交付说明。
**要做**：未指定区间用理解记录里的秒；manifest 写 `speech_lang`；点名 `lang:ja` 导出那条日文字幕文件（复制），视频时间仍以源语挂接为准；确认前只给计划。
**验收**：未确认计划同时有时间和 `zh`；点名日语交付物是 `lang:ja` 字幕，母版 sidecar 仍非日文全文。

### 7. 发出去之前看能不能用
**现在**：就绪只看封面、镜头、切片父链、有没有母版。
**要做**：源文件打不开则 `channel_ready` 为假；有声母版无源语挂接写进说明；某 `lang:` 在该任务字幕里不存在，写进 blocking 的是「缺这种语言」，任务仍可按已有语言导出。
**验收**：无 moov 任务不能就绪；只有中英字幕的任务查 `lang:ja` 报告缺日语，查 `lang:zh` 不因此失败。

### 8. 别的 Agent 读结构化结果
**现在**：已有 `hub://job`、`hub://shots`、`hub://related`。
**要做**：只读 `hub://understand/{id}`、`hub://run/{id}`；JSON 里 `lang` 与库内 `lang:` 一致。
**验收**：读到的 `speech.lang` 与步骤 4 相同；缺 id 报错，不编造某种语言的台词。

### 9. 用本库真有的数字验收
**现在**：门禁是中文 16 句；鸡翅和中文台词另有小标注；英文问句靠翻译桥没进同一张验收表。
**要做**：`ops_summary` 给出——画面中英双行齐全条数、源语已挂接条数、每个 `lang:` 字幕条数、坏文件数、导出次数、反馈采纳率；加两条不进旧门禁分母的检查：一条英文问句（chicken wings）、一条 `lang:ja` 过滤。
**验收**：语种计数与 `lang:` 标签一致；旧词法门禁仍单独通过。

### 10. 下次组装用上次被人留下的选择
**现在**：反馈日志不区分原文和译后词，组装包不读它。
**要做**：brief 记录原文语言和译后词；否决按译后词生效；被导出过的 id 仍须真实存在。
**验收**：英文否决 "indoor dialogue" 的译后词后，简体组装同一目标，brief 第一查询不再是那条词。

### 11. 检索按意图，第一屏就是要的那条
**现在**：非中文问句先翻译；意图词只有简体「台词/字幕」；面板「台词/画面」写死简体；一句中文台词拉出 100 多条（汉字 bigram 撞画面描述）。
**要做**：意图词翻译后判断（英文 "what was said" 译简体再走台词通道）+ 认 `lang:`；只提高汉字 bigram 在转写/画面通道重叠要求，拉丁单词权重保持 1，假名谚文不新增错误「汉字规则」；面板命中徽章走 `copy.ts` 三语；改完跑中文门禁 + 看英文 "chicken wings" + `lang:ja`。
**验收**：中文那句台词前三条仍是母版和音轨，总条数少于现在 149，门禁通过；英文 chicken wings 前排仍是那三张图；繁体界面徽章是繁体非简体「台词」。

### 12. 工作流固定、可解释
**现在**：链写死；Agent 技能词未覆盖全部界面语言。
**要做**：不增加工作流设计器；问答先按步骤 2 译到简体选链，再按界面语言描述 `index/run/<id>.json`；JSON 键保持英文（`thumb`/`asr`/`visual`）。
**验收**：英文界面问 "what ran on this asset"，答案与 JSON 步骤键一致，不出现链里没有的工具名。

**顺序**：1 → 4 → 7 → 11（先清挂接语种/理解字段/缺语言说明/跨语检索）；然后 2 → 6 → 5；最后 8 → 9 → 10；3 和 12 全程守住。11 若中文门禁失败只回退汉字重叠那一处；英文问句或 `lang:` 过滤变差同样只回退 11，不改「只保留一条源语」规则。

## 2. 网上最佳实践与商业模式

> 厂商案例和估算都标了出处，是销售材料不是独立审计。

### 商业模式
卖的不是网盘。卖的是：人定目标，Agent 把入库、打标、审核、改尺寸、发到渠道做完，人只处理例外。Cloudinary 原话：传统库回答「文件在哪」，Agent 库回答「下一步该对这条内容做什么，并且做掉」。

**谁买、为什么买**：买家是品牌、市场、电商内容团队，不是单个创作者。Cloudinary 点名零售、快消、金融、旅游、制造：内容量大，协调人（设计/本地化/法务/渠道）比做内容还贵。
五笔账（Cloudinary 企业指南）：上市速度（活动数周→快 40%–70%）、制作成本（改尺寸/裁切/多渠道适配交 Agent，第一年 −20%–40%）、个性化（一条母版出大量地区/受众版本，转化 +10%–25%）、素材复用（30%–50% → 60%+，少重做）、合规风险（过期授权/违规文案持续盯）。
Aprimo 数字：元数据自动 ~90%、合规校验快 ~70%、内容复用高 ~40%、查找快 ~50%；金佰利案例复用 +480%、审批 −80%、内容 +40% 不加人。

**怎么收费**（Canto）：①按团队规模和存储报价不公开单价；②只找文件/下载的「消费者」账号往往不按人头，编辑/管理员才计；③档位从基础库→带审阅/品牌模板/AI 搜索的协作档→大存储/专属实施/接 CRM·ERP 的企业档；④AI 打标/门户/基础集成可打进报价，实施另有一次性费；⑤卖点别再拆附加模块。
Cloudinary：平台 + 专用 Agent + 按需转码（不把每个衍生文件都存一份）；对外 MCP/API 让别的产品 Agent 调上传/元数据/变换/分析。

**产品形态**：一条内容链，几类专职 Agent，人在关键步点头。
- Aprimo 角色：规划（按数据和品牌策略写简报）、图书管理员（入库分类/打标/写说明）、评论（语气/清晰度/质量）、合规（已批准文案/法规）、制作（出渠道/本地化版本）、编排层串起来。
- Canto 四类：丰富元数据、合规、分发、治理。上传一批文件后系统按本品牌词表写元数据、对品牌和权利、标出能不能发、连产品记录，人打开前已跑完。
- Cloudinary 四产品 Agent：分类法、搜索、审核、工作流（工作流 Agent 先在对话给草稿，人点才存）。

### 最佳实践（12 条，按落地顺序）
1. 入库即动手（上传是事件不是等人点「识别」）。
2. 专职角色不是万能对话（打标/找素材/审品牌/出版本/往渠道送分开，共用上下文由编排层串）。
3. 先有本品牌词表再让模型填（分类法 Agent 可提议改词表，改不改人决定）。
4. 理解落结构化字段（画面/人/品牌元素/情绪/质量写成字段，下游读字段不是散文）。
5. 人审留会出事处（品牌/法务/对外发布要人点头；低价值协调交 Agent；目标是拿掉协调不是拿掉判断）。
6. 能改能发不只会搜（按自然语言目标拆步骤，变体按需生成避免每尺寸存一份母版）。
7. 权利在用的时候检查（过期肖像/活动/未批准文案发出前拦住，治理 Agent 还看外部渠道怎么被用）。
8. 库要能被别的 Agent 调用（MCP/API 露受治理的素材/元数据/变换/分析，下游拿时间/片段/可用版本）。
9. 用经营数字验收（复用率/审批时长/上市时间/查找时间/合规校验时长；人能从报表看 Agent 做了什么再用采纳否决训它）。
10. 学习来自两处（人批准或改掉哪条建议；哪条素材市场表现好）。
11. 搜索按意图结果要能用（「找出已批准、授权还在、这场活动能用的」，调用方不必先懂字段名）。
12. 工作流自然语言改底层走已有自动化（人描述「上传后打标/审/通知」，Agent 拟触发器和步骤，确认才写；业务规则变不为此改存储转码代码）。

Cloudinary 四条不要误会：不是搜索框加大模型；不是全程无人；不是买盒子就齐（媒体库/模型/编排/集成是一套架构）；最早吃到好处的是内容又多协调又贵的行业。

### 和本项目五条能力对照
| 桌面原文 | 厂商当成什么 |
|---|---|
| 上传后自己跑完解析 | 图书管理员/丰富元数据 Agent，入库事件触发 |
| 按画面/声音/人物/场景搜到时间点 | 搜索 Agent；理解层含人脸/品牌元素/语气 |
| 把时间轴和片段交给下游创作 Agent | MCP/API；分发 Agent 送渠道 |
| 近重复/无效片段/冷热/质检 | 库健康 + 审核 Agent；冷热是云存储账单一部分 |
| 规则可配：自动切片/版权/推下游 | 工作流 Agent；版权放合规/权利字段 |

厂商多出来、桌面原文没写成产品的：规划 Agent（先写活动简报）和「按市场表现加码表现好的版本」；收费多一块（按编辑席位和存储报价，消费者不按人头，实施另计）。

## 3. 与商业 DAM 的未对齐清单

> 对照 Cloudinary MAM 2026 / Canto Top 10 / Adobe 元数据 / 检索评估。核对日期 2026-10-08，只列还没对齐或只对齐一部分。
> 《素材中心最佳实践对照验证报告》把 A–R 都标 PASS（验「有没有对应功能」）；本清单验「和商业产品原文是否同一件事」。两份可同时成立。
> 已对齐不重复：单一索引、受控词表、混合检索和回归门禁、写操作留痕、外链不复制、去重、入库自动处理、MCP/CLI/面板。

### 未对齐（9）
1. **资产版本**：Canto/Cloudinary/Adobe 要求能回上一版已审批文件；本库更新覆盖索引，`history` 只记谁改标签/描述不保留文件本体，`trash/` 只回收索引。
2. **权利与到期**：Cloudinary 治理含授权范围/到期日/C2PA 溯源；库里无权利字段无到期提醒（素材自产暂未踩）。
3. **角色权限**：Canto 分管理员/贡献者/使用者，Cloudinary 要可定制细粒度；现只有可选 `VITUAL_HUB_TOKEN`，有即读写，跨机器文档写升 OAuth 代码无。
4. **人脸识别**：Canto AI 四件套含人脸；本库无人脸检测无人名库。
5. **按项目浏览非按类型**：Canto 主组织是项目/活动；面板主筛仍按图片/视频/无声/文档，`job:` 能筛非默认。
6. **归档与保留期限**：Canto 要定期审计后归档不只去重；本库无冷归档/保留期限/定时清理，失效外链手动清。
7. **审批流**：商业治理「未审批版本不能分发」；本库人工确认只挡 Agent 写库（`confirm=true`），无提交/审核/通过/驳回。
8. **元数据模式本身**：Adobe 要求先写清每字段目标/用途/谁能改/取值；字段散表和 sidecar 无模式说明。
9. **内容表现回流**：Aprimo 学习闭环看素材用多少/效果好再改推荐；现只有 Agent 动作采纳日志（`.agent_feedback.jsonl`），无播放/选用/发布后表现数据。

### 只对齐了一部分（8）
10. **描述性元数据**：技术事实（分辨率/时长/编码）已补多数；真说明画面的在 `index/visual/`，且 9 条损坏视频抽不出帧、1 条黑场编造已删，描述列故意不写派生文字。
11. **按镜头检索**：商业按场景切段各索引；本库用台词/画面行时间对已有镜头起止跳秒，没逐镜做描述向量（一条片子几十切点）。
12. **以文搜图**：商业放主结果；本库只文字 <3 条补 CLIP 且顶分 ≥0.32 且差 0.03 否则整批不要（鸡翅会把红印章排前），多帧 84/93 仍走守卫。
13. **重排**：商业召回后交叉编码器精排；代码在默认关，本机 ollama 不提供重排接口开了退回融合，候选已带画面/OCR/转写。
14. **台词检索干净度**：转写已挂同任务视频音轨能跳时间；一句完整台词带出百余条（画面描述双字也能得分），正确排前后面噪声。
15. **查询意图**：商业按「找文件/看画面/听台词」换通道门槛；现只识路径/编号/`type:`/`job:` 及「台词/字幕/说了」，其余同 0.25 余弦门槛。
