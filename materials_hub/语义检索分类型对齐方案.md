# 分类型语义检索对齐方案（待过目）

> 状态：步 1–5 已落到代码。词法门禁 PASS（p5 0.80 / r20 0.78 / mrr 0.91 / ndcg 0.91，基线 0.71 / 0.78 / 0.85 / 0.84）。
> 盘点日期：2026-10-08。语料 384 条，文本向量模型 `bge-m3:latest`，覆盖 384/384。
> 对照：面板「检索：自动 / 语义」走同一条 `search()`，不是按视频、音频、图片各做一套语义引擎。

## 1. 现在实际在搜什么

面板每次查询做两件事，然后用 RRF 合并：

1. 词法：文件名、标签、描述、路径，外加 OCR / 画面描述 sidecar（权重 0.35）。
2. 语义：把**整条素材**拼成一段文字，用 bge-m3 算一个向量。查询也是这段文字的向量。居中余弦低于 `0.25` 的条目直接丢掉（环境变量 `VITUAL_EMBED_MIN_COS`）。

这段文字来自 `doc_text()`：文件名、标签、描述、OCR sidecar、画面描述 sidecar、类型、目录末段。

因此「语义」搜到的是**这些文字的意思**，不是像素，也不是声波。

已有但**没有接进面板**的能力：

| 能力 | 入口 | 面板是否使用 |
|---|---|---|
| 以文搜图 CLIP | `search_by_text_image` | 自动 / 语义在文字命中少于 3 条时补入。顶分低于 0.32，或与第二名差距小于 0.03，整批丢弃（挡住 0.28 的印章簇）。文件名、编号、台词意图不走这一路 |
| 长文档分块 | `chunk_search` | 自动 / 语义把文档和字幕正文追加在已有排序之后。词法模式不读正文 |
| 镜头时间轴 | `get_shots` | 台词或带时间的画面行命中后写入 `hit_t` / `hit_shot`。卡片和详情里的视频会 seek 到这一秒。没有给每个镜头单独跑 VLM |
| 重排 | `VITUAL_RERANK_MODEL` | 默认仍关。打开后的候选文本包含画面描述、OCR、转写（各截 400 字） |

## 2. 按分类的缺口（实库）

| 分类 | 条数 | 文本向量 | 画面描述 | OCR | 语义真正能用的内容 | 缺口 |
|---|---:|---:|---:|---:|---|---|
| 图片 images | 157 | 157 | 157 | 110 | 文件名 + 画面描述文字 | 描述常把具体物体写成「食品 / 砖块」。CLIP 未进面板。鸡翅要靠描述里真有「鸡翅」 |
| 无声 silent | 77 | 77 | 77 | 75 | 同上，整段一个向量 | 多帧 CLIP 几乎没建。不能按镜头搜 |
| 视频 videos | 16 | 16 | **6** | **6** | 多数只有文件名 | 10 条母版没有画面描述。声音里的话没有进这条索引 |
| 动图 anim | 1 | 1 | 1 | 0 | 画面描述 | 与图片同一条路径，样本太少 |
| 音频 audio | 8 | 8 | 0 | 0 | 文件名、标签、短描述 | **没有转写文本**。语义只能撞上「wav / asr / 音轨」这类词，听不出内容 |
| 字幕 subs | 19 | 19 | 0 | 0 | 描述，不是 .srt 正文 | 正文只在 `chunk_search` 里，面板搜不到台词 |
| 文档 docs | 105 | 105 | 0 | 0 | 64 条有描述；41 条几乎只有文件名 | 正文同样只在分块检索，面板整篇一个向量 |
| 其他 other | 1 | 1 | 0 | 0 | 文件名 | 无专门通道 |

鸡翅这件事就是这张表的图片行：图在库里，描述写成「橙红色食品 / 红烧肉」，余弦最高约 0.17，低于 0.25，面板返回 0。后来只改正了 3 张已核对画面的描述。

## 3. 要对齐的做法

不引入云端多模态大模型。本地已经有 bge-m3、faster-whisper、画面 VLM、CLIP。做法按公开系统里反复出现、且能落在这套栈上的几条：

1. **词法 + 稠密，用名次融合，不把两种分数加在一起。** BM25/词法分数和余弦不在一个量纲。RRF 是通用解法（[Hybrid Search for RAG, 2026](https://denser.ai/blog/hybrid-search-for-rag/)）。本库已经在用 RRF，保留。
2. **视频按场景切段，每段单独索引，而不是整片一个向量。** 画面、声音、转写分开存，查询时按意图加权，再融合（[Amazon Nova 视频语义检索](https://aws.amazon.com/blogs/machine-learning/power-video-semantic-search-with-amazon-nova-multimodal-embeddings/)）。本库已有 `index/shots`，但检索粒度仍是整条素材。
3. **语音先转写，再对转写做词法 + 文本向量；命中要能跳到时间。** 生产系统按说话轮次建索引，关键词和向量各走一路（[AssemblyAI: transcript search](https://www.assemblyai.com/blog/transcript-search)）。CLAP 这类「声音↔短标题」模型对台词语义弱（ACL 2026 ATIR：跨模态音频检索 Recall@1 远低于先转写再做文本检索）。本项目已有 `subtitle_pipeline/multipass_asr.py`（faster-whisper），素材中心还没把转写收进检索。
4. **画面查询走视觉通道，专有名词走词法。** 视觉嵌入擅长「一盘酱汁鸡翅」，不擅长文件名、型号、任务 id。两类查询不要挤在同一个 0.25 门槛后面。
5. **重排只看召回后的一小截，并且候选文本必须包含画面描述、OCR、转写。** 现在的重排文档把这些 sidecar 排除了，等于精排时看不见真正命中的字段。

明确不采用：把 OCR / 画面描述 / 转写写进数据库 `description`（权重 1.5）。历史教训是门禁 nDCG 从 0.84 掉到 0.80。新文本继续只进 sidecar 和独立通道。

## 4. 分步对齐（实现前先过目）

每步都保持 `eval_search.py --mode lexical --gate` 不退步。新的画面 / 台词查询另建一份小标注，不拿去改旧门禁的分母。

### 步 0 — 口径（本文）

确认下面的顺序和「不做」清单。未确认前不改 `search()`。

### 步 1 — 把已有通道接进面板，按类型分流

`search(mode=auto|semantic)` 在现有词法 + bge 之外补两路，只加召回，不改旧词法排序公式：

- 图片 / 无声 / 视频 / 动图：若词法命中很少，并入 `search_by_text_image` 的高分结果，并标明命中来自画面。
- 文档 / 字幕：并入 `chunk_search`，命中正文段落，而不是只看描述。
- 音频、纯文件名查询：这一步仍只有现有文本向量。不要假装已经能「听懂」。

界面：语义模式下列出命中依据（文件名 / 画面描述 / 字幕段落 / 画面向量），避免再出现「共 384」被当成搜索结果。

### 步 2 — 补齐视频画面描述，并改成按镜头

- 先把 10 条没有 `index/visual` 的视频补上。描述必须写具体物体，拒答句不入库。
- 检索单位从「整条视频一个向量」改为「每个 shot 一段描述 + 一个向量」，结果带回 `t_start`。
- 多帧 CLIP 从现在的 2 条素材扩到视频类。CLIP 只做补充召回，主证据仍是画面描述文字（本库已验证 CLIP 对「鸡翅」会把红印章排到前面）。

### 步 3 — 音频与带声视频的台词

- 不重跑 Whisper。流水线已经写出 `.srt`。同 `job:` 下优先 `zh.srt`，挂到该任务的视频和音轨：`index/asr/<id>.txt`，每行带时间。
- 词法走独立 0.35 通道（与 OCR 相同，单字不计分）；语义经 `doc_text` 读 sidecar。不写 `description`。
- 多语字幕不全部挂上，避免 16 种译文把母版向量冲散。
- 没有 `job:`、也没有同任务字幕的成片，这一步挂不上。那是登记时没写任务号，不是再转写能解决的。
- 字幕文件本身：自动 / 语义检索追加正文命中（已做）。
- 命中行里带时间范围。面板上点开仍是整条素材，按时码跳转还没做。

### 步 4 — 查询意图与门槛

- 文件名、id、扩展名、`type:` / `job:`：词法优先，语义门槛维持 0.25，避免泛词把全库拉进来。
- 看画面（食物、物体、场景）：允许视觉通道的较低门槛，并且必须带回画面证据。
- 听内容（说了什么、台词）：只走转写 / 字幕通道。
- 重排候选文本改为 name + description + 画面描述 + OCR + 转写片段。默认仍关闭，有本地 reranker 再开。

### 步 5 — 验收

| 查询 | 应命中 | 不应发生 |
|---|---|---|
| 鸡翅 | 已核对的 3 张酱汁鸡翅（auto：P@5 0.60，R@20 1.00，MRR 1.00；前三名就是这三张） | 红印章靠 CLIP 0.28 挤到前面。另有一份小标注 `eval_gt_visual_speech.json`，不进旧门禁分母 |
| 台词里的原句 | 对应 subs 或 ASR 时间段 | 只因为文件名带 srt 就命中全部字幕 |
| wav / 音轨 | 音频文件仍能被类型词找到 | 没转写的音频被说成「已按内容搜到」 |
| 旧门禁 16 句 | lexical gate 仍 PASS | 新 sidecar 写进 description |

## 已改（2026-10-08，贴链接之后的两处断点）

对照 `PIPELINE_BEST_PRACTICES.md` 的收尾：`hub_push` → `run_job_dir` → `do_auto` → `auto_process_material`。

1. **画面描述不算缺项。** `pending_processing` 原先只看封面、OCR、镜头、pHash。视频一旦这四项齐了，后面的自动处理就跳过，`visual_material` 不会再跑。所以 16 条视频里有 10 条没有画面描述。现在缺 `index/visual/<id>.txt` 会标成待处理，下次入库或 `auto` 会补。
2. **字幕和文档正文不进面板。** 自动 / 语义检索在原排序之后，追加 `.srt` / 笔记正文的命中，不插入到词法结果前面。词法模式和检索门禁路径不变。
3. **台词挂到片子上。** `attach_job_transcripts()`：同 `job:` 的中文字幕写入 `index/asr/<id>.txt`，视频和音轨用 0.35 权重可搜。`run_job_dir` 登记后会跑。没有同任务字幕的成片不会凭空出现转写。
4. **CLIP 只补空结果。** `_append_clip_hits`：文字得分大于 0 的条目已有 3 条就不再叫 CLIP。叫了也要顶分 ≥ 0.32 且比第二名高出 0.03，否则整批不要。`type:` / `job:` / 路径 / 纯十六进制 id，以及查询里带「台词 / 字幕 / 说了」，直接跳过。
5. **命中时间。** `_mark_hit` 用双字词对上转写行或 `[12.5s]` 画面行，填 `hit_t`、`hit_shot`、`hit_end`。面板视频 `onLoadedMetadata` 把播放头放到这一秒，卡片上标「台词 / 画面」。
6. **门槛。** 全库余弦仍是 0.25。没有为「看画面」单独下调。画面证据来自 sidecar 词法，或上面这条有间隙的 CLIP。
7. **缺画面描述的 10 条视频。** 其中 9 条源文件没有 moov（ffmpeg 报 `moov atom not found`，有的只有几十字节），抽不出帧。`df15038ba7ca` 能打开，但开头几帧是黑场，VLM 编了「红烧肉」。这条 sidecar 已删掉，没有写进检索。抽帧在快进得到空文件时会再做一次精确 seek，开头仍抽不出画面就保持缺描述。多帧 CLIP 已对视频和无声片段建完：93 条里 84 条有帧向量（抽不出帧的 9 条跳过）。查询仍要过 0.32 / 0.03 的间隙，才允许补进面板。

按镜头的做法是：转写或画面行上的时间落进已有 `index/shots` 的场景区间，结果带镜头起点。没有对每个场景再跑一遍 VLM（单条片子可以有几十个切点）。

## 5. 这一轮不做

- 不换云端视频嵌入，不上 CLAP 作为语音主索引。
- 不把 384 条画面描述全部重跑。只补缺的视频，以及验收集里确认看错的图片。
- 不改分类法（master / shot / silent / audio-stem 仍按方案 A）。
- 不在本文确认前改排序权重或 `0.25` 门槛。
